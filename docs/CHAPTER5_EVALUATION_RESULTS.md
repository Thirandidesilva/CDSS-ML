# Chapter 5 — Evaluation and Results

This chapter evaluates the system under three frameworks: **Usability** (does a real
owner find it clear and useful), **Functionality** (does each part of the system do
what it is supposed to do), and **Accuracy** (how good is each model, on the metric
that is actually appropriate to it). Every number below carries a status tag —
**regenerated** (produced by a script in this repository, command given) or
**flagged discrepancy** (this repository's own result disagrees with an earlier
figure, both stated rather than one silently preferred) — following the status
discipline already established for this project in `docs/THESIS_GUIDE.md` and
`.claude/docs/FACTS.md`. No number in this chapter is invented or assumed.

---

## 5.1 Introduction

A CDSS cannot be evaluated on a single axis. Usability asks whether the intended
users — dog owners with no clinical training — can actually operate the system and
find its output meaningful. Functionality asks whether the software, across its three
components (the ML pipeline, the backend API, and the mobile application), behaves
correctly against its own specification. Accuracy asks how good each model inside the
pipeline actually is, measured on the terms appropriate to what that model is: a
measurement model is evaluated on reliability, not classification accuracy; a
classifier is evaluated on classification metrics. Conflating the three, or applying
one metric shape (e.g. AUC/F1) uniformly regardless of what a component actually is,
would misrepresent the system — this is the same discipline the project already
applies to its own central methodological finding (§5.4, and `docs/THESIS_GUIDE.md`
§4): a result computed on the wrong basis is worse than no result.

## 5.4 Accuracy Evaluation

Generated by `python src/evaluate_accuracy.py`; full result:
`results/accuracy_evaluation.json`. The pipeline has three components that are not the
same kind of model, so each is evaluated on the metric appropriate to it rather than
forcing every row into an AUC/F1 shape:

- The **IRT/GRM severity model** is a *measurement model*: it estimates a continuous
  latent trait (theta), not a class label, so it is evaluated on measurement
  properties — reliability and standard error — not classification accuracy.
- **k-means phenotype clustering** has no ground-truth label to classify against
  either (there is no external "correct" phenotype), so it is evaluated on internal
  cohesion and re-run stability.
- The **Random Forest phenotype-confidence classifier** is the one component that
  genuinely performs classification (predicting the nearest-centroid phenotype label
  from the 12 raw items), so it is the one component reported with AUC, F1, precision,
  recall, and a confusion matrix.

This split is not incidental. The project's own central methodological finding
(`docs/THESIS_GUIDE.md` §4) is that the *original* design derived a severity label
from the same 12 items it then tried to predict from — a classifier "learning
arithmetic, not anxiety," reaching a trivial 1.000 accuracy for exactly that reason.
Manufacturing a classification target for theta here would reproduce the same
circularity. Reporting reliability/stability for the two non-classification components
instead is a deliberate methodological choice, not a gap.

*Status: regenerated, `python src/evaluate_accuracy.py`.*

A low absolute silhouette score (0.12) alongside high label stability (ARI ≥ 0.91
across every reseed) is not a contradiction: silhouette measures how cleanly
*separated* the three clusters are in raw item space (modest, since anxiety phenotypes
form a continuum rather than tight, well-separated groups), while the stability
figure measures whether the *same dogs* get the *same label* regardless of k-means'
random initialisation — which they reliably do. The clustering is reproducible even
though the clusters themselves are not sharply separated.

**What this accuracy figure is, and is not, evidence of.** 0.9018 accuracy is

label*, both derived from the same 12 items. It is evidence the forest can recover the
clustering's own structure reliably — the basis for treating its output as a usable
*confidence* signal (`flag_rf` in the pipeline) — not evidence of agreement with any
external, clinically-validated phenotype. No veterinary-labelled ground truth exists
yet (`docs/THESIS_GUIDE.md` §10, Phase 14, blocked); this limitation applies to every
accuracy figure in this section and must be restated wherever these numbers are
quoted elsewhere in the thesis.

## 5.5 Summary

Functionality is fully evidenced: 91 of 91 automated tests pass across the backend,
API, and ML core, with the report/PDF subsystem correctly flagged as still
uncommitted; mobile functionality has a defined manual test plan awaiting execution.
Accuracy is evidenced per-component on the metric appropriate to each: the IRT
measurement model on reliability and fit (with one open discrepancy against the prior
analysis, flagged rather than resolved silently), the clustering on internal
stability, and the Random Forest classifier on genuine out-of-fold classification
metrics (90.2% accuracy, 0.90 macro F1, 0.98 macro AUC) — all independent of, and
computed fresh from, this repository's own current artefacts. Usability remains
outstanding pending real user data collection. None of these figures constitute a
clinical accuracy or validity claim about the system as a whole: that requires
veterinary labels, which do not yet exist (`docs/THESIS_GUIDE.md` §10).
